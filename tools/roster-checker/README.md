# 团员花名册核查工具

给团委用的花名册核查脚本：**把 Excel 花名册和智慧团建系统里的人数、班级、缺失情况对起来**，
输出一份能直接发给学院负责人的清单。

> 实战战绩：某高校 2026 级两个学院 394 人，查出
> 系统里没有 96 人、班级不符 6 人、学号重复 2 人、表格内重复 1 人。

---

## 它解决什么问题

每年新生入学，团委手上会有一份各学院报上来的花名册；智慧团建系统里另有一份。
两边经常对不上：

| 现象 | 后果 |
|---|---|
| 表里有、系统里没有 | 学生团组织关系没转接，评优、转正都会卡 |
| 系统里有、表里没有 | 漏报，材料少人 |
| 两边都有但班级不同 | 转到别的支部去了，没人跟进 |
| 同一人在表里出现两次 | 人数统计错误 |
| 籍贯写成了县、时间写成 `2023/6/1` | 审核不过，要打回重填 |

手工核 400 人，一个人要来回翻两次表，一天也核不完。这套脚本把它变成 5 分钟。

---

## 三条硬规矩（先看这个）

1. **数据不出本机。** 花名册、系统导出、所有输出都在本地，仓库里一个都没有。
   `config.json`、`输出/` 都写在 `.gitignore` 里。
2. **只核对，不修改。** 脚本只读数据、只出报告，不会碰你的原始表格和系统。
3. **系统数据靠你自己导出。** 脚本不会去登录智慧团建——它没有你的密码，也不该有。

## 怎么用

### 0. 准备

- Python 3.8+（`openpyxl`，其余全标准库）
- 花名册 xlsx（各学院分段的那份大表）
- 智慧团建导出的 csv（`团支部,姓名,手机号,职务`）

### 1. 配置

把 `config.example.json` 复制成 `config.json`，填三样东西：

```json
{
  "roster":  "D:/团委档案/团员花名册-2026级*.xlsx",
  "sys_csv": "C:/Users/你的用户名/Downloads/智慧团建-团员名单*.csv",
  "colleges": ["机械学院", "人工智能学院"]
}
```

路径支持通配符，有多个匹配时自动取最新的那个——这样系统第一次导出、第二次导出都在下载目录里也不会选错。

### 2. 从智慧团建导出名单

系统**没有**批量导出按钮（校级那个"导出直属下级团支部成员"只导出直属支部，
进到学院层级就没有了）。只能用脚本从页面抓：

1. 登录智慧团建 → 团员管理 → 团员列表
2. 点进某个学院，让右侧显示该学院的团支部列表
3. F12 → Console → 粘贴 `scripts/0_提取智慧团建.js` 整段 → 回车
4. 跑完执行 `导出团员()`，得到 csv

> 脚本在你**已登录的浏览器**里跑，用的是页面自带的登录态。不需要、也不应该把账号密码交给任何人。

### 3. 跑

双击 `开始.bat`，按菜单走；或者直接跑脚本：

```
python scripts\3_核查_表格内.py     # 表格自身的问题
python scripts\4_对账.py            # 和系统对账
python scripts\5_出总表.py          # 出名单（提交版 + 复核版）
python scripts\6_人数统计.py        # 人数 + 缺失名单
python scripts\7_分学院.py          # 按学院拆开
```

## 核查哪些项

| # | 项目 | 判定标准 |
|---|---|---|
| 1 | **籍贯** | 必须「省+市」。`浙江杭州`✅ `浙江省丽水市`✅ `浙江遂昌`❌（县）`浙江省温州市泰顺县`❌（多写） |
| 2 | **系统缺失** | 表里有、系统里查不到 |
| 3 | **班级不符** | 两边都有但班级不同。**先全表找一遍再判定**：在别的班找到 → 班级不符；整个表都没有 → 才算缺失 |
| 4 | **重复** | 同一人出现两次；两人共用一个学号 |
| 5 | **时间格式** | 出生年月、入团时间必须 `2024.9`（到月、点号分隔）。`2023/6/1`、`2024`、`2023,12` 都不行 |
| 6 | **备注为空** | 备注应填政治面貌 |

判定口径以团委实际要求为准，不同学校可能不同，改 `scripts/3_核查_表格内.py` 里的函数即可。

---

## 籍贯怎么判出来的

「遂昌是县还是市」这种事，人肉判断很容易错，所以脚本自带一份**真实行政区划数据**
（省 → 市 → 区县，2978 条，仓库里自带 `data/行政区划.csv`，103 KB，**离线可用**）。

于是它不只说"错了"，还能告诉你该改成什么：

```
浙江省慈溪市      → "慈溪"是县级，应改为"浙江宁波"
四川省盐亭县      → "盐亭"是县级，应改为"四川绵阳"
浙江绍兴绍兴      → 市名重复写了两次
安徽毫州          → 疑似"亳州"（可能写错字）
```

## 专业简称

各学院写法五花八门（`材料科学与工程261班` / `数字媒体艺术专业专升本261班` / 纯 `土木`），
所以有一张可编辑的简称表 `data/专业简称.csv`：

```
学院,专业全称,简称,人数
人工智能学院,计算机科学与技术,计算机,96
机械学院,机械设计制造及自动化,机制,89
```

`8_生成简称表.py` 会扫描花名册自动生成这张表；哪个简称不满意，改 csv 里一个词就生效。
脚本靠它把「花名册的 智能制造工程263」和「系统的 智能制造工程专业2026级3班团支部」对上——
**换一个学院、换一份花名册，不用改代码**。

## 输出什么

```
输出/
  核查结果-表格内问题.xlsx    籍贯/时间/备注/重复
  对账结果.xlsx              缺失/班级不符
  团员花名册有误名单.xlsx     逐人清单（提交给主任）
  团员花名册有误名单-复核版.xlsx  带「应改为」和分类表，自己复核用
  团员人数统计.xlsx          按学院/按班级人数 + 缺失人员名单
  机械学院-2026级团员核查.xlsx  ← 直接发给学院负责人
  数据学院-2026级团员核查.xlsx
```

名单遵循**一人一行**：同一人身上的多个问题合成一句，例如

```
张三  智慧团建无，表格里有，且表格里出现两次
李四  智慧团建无，表格里有，且学号与王五相同
王五  学号与李四相同
赵六  智慧团建上为信计261，与表格不符
```

## 已知问题

**① 「幽灵团支部」——系统 bug**

遇到过这种情况：某个支部在**左侧组织树里能点进去、也能看到成员**，但右侧的团支部列表
**根本不显示它**。列表接口和树接口不是同一套查询，建了支部但状态不对就会被过滤掉。

后果：脚本按列表抓，抓不到这个班。

对策：手动点进那个支部，跑 `0_提取智慧团建.js` 末尾的 `抓取当前支部()`，
再把抄到的名字填进 `config.json` 的 `ghost_branches`：

```json
{
  "ghost_branches": {
    "智能制造工程264": ["姓名1", "姓名2", "姓名3"]
  }
}
```

（放在 config.json 而不是代码里，是因为这些是真实姓名，不能进仓库。）

建议同时反馈给系统管理员——这种数据不一致以后还会出事。

**② 系统里没有学号**

智慧团建导出的字段是 `团支部/姓名/手机号/职务`，没有学号。
所以对账只能按姓名匹配，重名会误判。目前做法：姓名相同但学号冲突的单独标"需人工确认"。

**③ 名字打错字查不出来**

系统里写成「陈鸣」、花名册是「陈明」，脚本只能靠模糊匹配提示"疑似"，
最终要人确认。这种错字光看任何一边都发现不了。
